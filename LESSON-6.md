## Что сделано

### 1. ProtectedRoute и useAuth

- Фича features/auth-routing: AuthContext, AuthProvider, хук useAuth и ProtectedRoute
- ProtectedRoute берет сессию из контекста, без нее рендерит Navigate на /login с replace, иначе Outlet
- Защищенные страницы подключены детьми роута с ProtectedRoute, /login, /register и /public публичные
- Сессия читается из localStorage лениво в useState, то есть уже на первом рендере, поэтому после F5 нет ни мигания, ни лишнего редиректа
- localStorage знает только AuthProvider, компоненты работают с контекстом
- useAuth бросает ошибку вне провайдера, чтобы не ловить undefined

### 2. LoginPage

- Форма в features/login-form на react-hook-form и zod, поля email и password обязательны, переиспользован TextField из shared
- Запрос через RTK Query: authApi в shared/api, useLoginMutation бьет в POST /auth/login учебного API
- Ответ сервера это user и accessToken, они уходят в login из контекста, тот же метод пишет сессию в localStorage
- При ошибке сервера сообщение кладется в errors.root и показывается под формой, на время запроса кнопка блокируется
- После успеха navigate на /profile с replace, чтобы кнопка назад не возвращала на форму входа

### 3. ProfilePage

- Страница лежит под ProtectedRoute, поэтому без сессии до нее не дойти
- Имя и email тянутся с сервера через useGetMeQuery, это GET /users/me
- Токен берется из контекста и передается в запрос аргументом, оттуда уходит в заголовок Authorization, сам слой запросов в localStorage не лезет
- Сервер отдает accessToken уже с префиксом Bearer, поэтому в заголовок он кладется как есть, без второго Bearer
- До появления токена запрос пропускается через skipToken
- После F5 сессия восстанавливается из localStorage, RTK Query заново запрашивает /users/me, имя снова на месте

### Дополнительная задача

- Публичный маршрут /public вне ProtectedRoute, открыт всем и после выхода тоже
- Кнопка Выйти на профиле вызывает logout, он чистит контекст и localStorage, затем navigate на /login с replace
- После выхода сессии нет, поэтому ProtectedRoute отправляет с /profile на /login даже при заходе по прямой ссылке
